# ADR 002. Собственный движок маршрутизации

- **Статус:** принято (реконструировано по коду и [routing.md](../routing.md))
- **Дата появления кода:** 2026-09-21 (`backend/routing/astar.js`, коммит `56c1b53`)

## Контекст

Геометрию маршрута раньше строил публичный демо-сервер OSRM, и браузер
отправлял ему точные координаты пользователя и всех точек маршрута. Внешней
модели при этом передавалась метка `@HOME` вместо адреса — координаты же
уходили третьей стороне без договора ([api/route.js](../../backend/api/route.js),
заголовочный комментарий).

Целевой сервер — одно ядро и 2 ГБ памяти ([routing.md](../routing.md)).

## Решение

Строить маршруты и матрицу времени в пути собственным движком внутри
доверенного контура: граф дорог Казани из OpenStreetMap в формате CSR на
типизированных массивах, A* для маршрута, Дейкстра «один ко многим» с
потолком времени для фильтров, привязка точки к отрезку дороги в главной
компоненте связности ([09-routing-engine.md](../09-routing-engine.md)).

## Рассмотренные варианты

| Вариант | Почему отклонён (по [routing.md](../routing.md)) |
|---|---|
| Публичный OSRM | передача координат третьей стороне; не рассчитан на промышленную нагрузку |
| Свой OSRM | подготовка данных требует кратно больше памяти, чем весит выгрузка; рантайм держит граф целиком |
| GraphHopper | JVM с отдельной кучей от гигабайта |
| Valhalla | тяжёлая сборка и контейнер для такой машины |

## Последствия

- Координаты не покидают сервер; из CSP убран последний сторонний хост в
  `connect-src`.
- Граф (~10 МБ файл, ~20 МБ в памяти с состоянием поиска на графе,
  замеренном при аудите) собирается офлайн и обновляется без перезапуска.
- Нет пробок, общественного транспорта и запретов поворотов — время
  считается по свободному потоку.
- Поиск идёт в основном потоке, поэтому понадобились бюджеты процессорного
  времени ([05-backend.md](../05-backend.md)).
