# ADR 004. SQLite через встроенный `node:sqlite`

- **Статус:** принято (реконструировано по коду и [accounts.md](../accounts.md))
- **Дата появления кода:** 2026-10-08 (кабинет, `backend/accounts/sqliteStore.js`,
  коммит `95d8a08`); 2026-10-09 (демо-запись, `backend/demo/bookingStore.js`,
  коммит `62ec31a`)

## Контекст

Кабинету нужны пользователи, сессии и избранное; демо-записи — слоты с
атомарными переходами состояний. Сервер — одно ядро и 2 ГБ; нагрузка — единицы
запросов в секунду; серверный код проекта не имеет npm-зависимостей в
рантайме.

## Решение

Один файл SQLite на подсистему через встроенный модуль `node:sqlite`
(`DatabaseSync`): WAL, `busy_timeout`, миграции по `PRAGMA user_version`,
транзакции `BEGIN IMMEDIATE` для переходов слота. На Node без `node:sqlite`
(до 22.13) кабинет и демо-запись выключаются, остальной сайт работает.

## Рассмотренные варианты

| Вариант | Комментарий |
|---|---|
| PostgreSQL | запланирован для кабинета: `service.js` не знает про SQL, переход — новый `pgStore.js` с теми же методами ([accounts.md](../accounts.md)) |
| Внешняя библиотека SQLite | противоречит отсутствию runtime-зависимостей; в документах проекта не обсуждалась |

## Последствия

- Нет отдельного процесса СУБД; резервная копия — `sqlite3 … ".backup"`.
- Запросы синхронные и выполняются в основном потоке.
- Масштабирование на несколько экземпляров сервера потребует смены хранилища.
