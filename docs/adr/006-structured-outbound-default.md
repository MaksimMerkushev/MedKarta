# ADR 006. Режим `structured` по умолчанию

- **Статус:** принято (реконструировано по коду и [privacy-architecture.md](../privacy-architecture.md))
- **Дата:** не зафиксирована; решение действует в версии политики
  `2026-10-05.1` (`POLICY_VERSION` в [policies.js](../../backend/privacy/policies.js))

## Контекст

После второго аудита приватности слова пользователя уходили внешней модели,
только если каждое из них входило в закрытый словарь. Измерение на
размеченном наборе показало, что словарь пропускает имена, совпадающие с
обычными словами («Жене нужен терапевт»: «жене» — слово словаря)
([privacy-architecture.md](../privacy-architecture.md), раздел 9;
[privacy-evaluation.md](../privacy-evaluation.md)).

## Решение

По умолчанию (`PRIVACY_OUTBOUND_MODE=structured`) модель получает **только
описание**, собранное из перечислимых значений: ключи профилей, места из
закрытых списков, ограничения, метки и порядок шагов. Слов пользователя в
запросе нет никогда. Режим `hybrid` (слова — если все из словаря) оставлен
как настройка.

## Рассмотренные варианты

| Вариант | Итог |
|---|---|
| `hybrid` по умолчанию | точнее формулировка, но известны утечки имён-слов: при аудите — 3 на 14 622 примерах ([07-privacy.md](../07-privacy.md)) |
| Расширять детекторы | «у подхода „ищем известные виды данных“ нет дна» ([privacy-architecture.md](../privacy-architecture.md)) |

## Последствия

- В режиме `structured` утечек на размеченном наборе нет (0 из 14 622 при
  аудите); проверки, защищающие текст, в этом режиме не отключают модель.
- Чтобы смысл не терялся, описание дополнено порядком шагов, улицами без
  номеров домов, стажем, сортировкой, способом передвижения и условиями из
  всех реплик.
- «Привет», «спасибо» и запросы без цели отвечаются локально — модели нечего
  планировать.

`npm run test:security` (весь набор в обоих режимах), `npm run eval:privacy`.
