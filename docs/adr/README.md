# Архитектурные решения (ADR)

ADR фиксирует решение, контекст и рассмотренные альтернативы. ADR 001 написан
вместе с решением. ADR 002–006 **реконструированы** при аудите документации:
решения уже реализованы в коде, а обоснование собрано из комментариев в
исходниках и существующих документов. Дата в них — дата появления
соответствующего кода в истории git, а не дата обсуждения.

| № | Решение | Статус |
|---|---|---|
| [001](001-external-llm-privacy-boundary.md) | Граница приватности при работе с внешним LLM: Privacy Gateway и модель-планировщик | Принято |
| [002](002-own-routing-engine.md) | Собственный движок маршрутизации на типизированных массивах вместо OSRM и аналогов | Принято (реконструировано) |
| [003](003-deterministic-booking-conditions.md) | Условия записи исполняет детерминированный код, а не модель | Принято (реконструировано) |
| [004](004-sqlite-builtin.md) | SQLite через встроенный `node:sqlite` для кабинета и демо-записи | Принято (реконструировано) |
| [005](005-security-headers-in-code.md) | Заголовки безопасности и лимиты — в коде сервера, а не в настройках хостинга | Принято (реконструировано) |
| [006](006-structured-outbound-default.md) | Режим `structured` по умолчанию: модель не видит слов пользователя | Принято (реконструировано) |

Шаблон нового ADR: «Статус», «Дата», «Контекст», «Решение», «Рассмотренные
варианты», «Последствия», «Где в коде», «Как проверяется».
