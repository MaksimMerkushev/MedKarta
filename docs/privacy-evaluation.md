# Проверка обезличивания на размеченном наборе

Как измеряется, уходит ли модели что-то из персональных данных и что
теряется по смыслу. Код — `tools/privacy-eval/`, запуск — `npm run eval:privacy`,
регрессия в `npm test` — `tests/privacy-eval.test.js`.

## Что считается

Каждый пример прогоняется через настоящий конвейер (`createPipeline`) с
настоящим справочником. Вместо сети стоит заглушка: она записывает всё, что
ушло бы модели, кроме неизменного системного промпта, и отвечает «уточните».
Дальше по записанному:

- **утечка** — в исходящем тексте нашлось размеченное значение: имя или
  фамилия целым словом в любой форме написания, 5 цифр телефона подряд,
  6 цифр документа или даты рождения, 4 слова телефона «словами», локальная
  часть почты, номер дома рядом с улицей, медицинское слово. Цель — 0;
- **ушло модели / ответили локально** — для примеров с данными;
- **обычные запросы** — сколько дошло до модели, сколько дошло без
  изменений (режим `hybrid`), сколько испорчено лишними метками;
- **смысл дошёл** — есть ли в исходящем профиль врача, время, место
  (район, ориентир, «рядом», улица), детский приём, ДМС, способ
  передвижения, клиника, порядок шагов маршрута, стаж, сортировка. В
  описании порядок засчитывается только по строке «Порядок в запросе»;
- **реплики без запроса** («привет», «спасибо») — должны отвечаться
  локально;
- время разбора одного запроса.

## Набор

| Часть | Примеров | Что внутри |
|---|---:|---|
| Проверочная (`--split test`) | 11 349 | генератор, свои имена и шаблоны |
| Обучающая (`--split train`) | 11 200 | генератор, другие имена и шаблоны |
| Ручная (`--split handwritten`) | 149 | написано вручную, как пишут в чате |

Генератор детерминирован (seed 7). Имена и фамилии делятся между частями по
хешу: имени из проверочной части нет в обучающей. Имена склоняются по пяти
падежам, пишутся пятью способами: обычно, строчными, ЗАГЛАВНЫМИ, с опечаткой,
латиницей. Группы: родственники (2400), сам пользователь (900), врач вне
справочника (600), имя во второй реплике (300), уменьшительные (400),
имена-слова — Вера, Роза, Лев (200), телефоны (500), почта (250), адреса
(500), документы (400), медицинский текст (300), всё вместе (300), врачи
справочника (300), обычные запросы (1500), обычные «как в жизни» —
опечатки, сленг, лекарства (800), маршруты из нескольких шагов (600),
улицы без номера дома (400), стаж / сортировка / травмпункт (400),
реплики без запроса (150).

Набор синтетический. Он показывает, где система ломается, но не доказывает,
что живые пользователи не напишут иначе: ручная часть и новые жалобы из
продакшена должны его пополнять.

## Результаты, 05.10.2026

Режим `structured` — по умолчанию. Режим `hybrid` — `PRIVACY_OUTBOUND_MODE=hybrid`.

| | structured | hybrid |
|---|---:|---:|
| **Примеры с данными, все три части** | 14 728 | 14 728 |
| Утечки | **0** | 2 («Жене нужен терапевт»: «Жене» есть в словаре как «жене») |
| С данными: ушло модели обезличенным, test / train / ручная | 88,7 / 86,1 / 82,1 % | 79,2 / 79,6 / 81,1 % |
| Обычные запросы: дошли до модели, test / train / ручная | 100 / 98,0 / 100 % | 100 / 99,9 / 100 % |
| Обычные запросы: дошли словами пользователя | 0 % | 45 / 60 / 78 % |
| «Привет», «спасибо»: ушли модели | 0 % | 29–43 % |
| Профиль / время / место дошли | 100 / 100 / 100 % | 100 / 100 / 99,2–99,4 % |
| Порядок шагов маршрута | 99,8–100 % | 99,8–100 % |
| Стаж, сортировка, транспорт, ДМС, клиника | 100 % | 100 % |
| Отменено выходным предохранителем | 0 | 0 |
| Разбор запроса, p50 / p95 | ≈4 / 10 мс | ≈4 / 10 мс |

Что остаётся локальным в `structured` и почему (проверочная часть):
документы — 308 (правило: СНИЛС, полис, паспорт наружу не отправляются
никогда); реплики, в которых кроме телефона или почты ничего нет, — 370
(модели нечего планировать, а план без шагов исполнитель всё равно отклонил
бы); «хочу к доктору Пупкину», когда такого врача нет в справочнике, — 82
(локальный ответ говорит об этом прямо); буквы через пробел — 70 (ответ
просит написать обычным текстом). На обучающей части
69 обычных запросов вида «кто принимает до обеда?» тоже отвечаются локально:
без профиля исполнимого плана нет и у модели.

Цифры выше получены с полной базой врачей (`data/doctors.full.js`, 681
врач; в git её нет). На публичном срезе (6 врачей) картина та же:
проверочная часть — в `structured` 0 утечек, модели ушло 87,3 % примеров с
данными; в `hybrid` 3 утечки — все «Жене нужен …».

Для сравнения — до этой работы, на старой версии проверочной части (9 799
примеров): только детекторы находили 75,8 % имён (строчными — 43,1 %,
уменьшительные — 33,6 %). Утечек не было лишь потому, что всё
нераспознанное уходило описанием, а не текстом.

## Что не измеряется

- Ответ модели. Заглушка всегда отвечает «уточните»: качество плана на
  описании вместо текста нужно проверять отдельно, на реальной модели.
- Утечка по смыслу без самих значений: «моя соседка по лестничной клетке с
  ВИЧ» без имени — не утечка по этой метрике.
- Записи с ошибками разметки: «Малышев» больше не считается «малышом»,
  остальные подобные случаи разбираются по примерам (`--examples 30`).

## Как запускать

```bash
npm run eval:privacy                                  # проверочная + ручная, режим по умолчанию
npm run eval:privacy -- --mode hybrid                 # другой режим
npm run eval:privacy -- --split all --examples 30     # всё и примеры ошибок
npm run eval:privacy -- --scale 0.2 --out /tmp/e.json # быстро, с сохранением результатов
```
