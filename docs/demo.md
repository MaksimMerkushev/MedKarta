# Демо-среда: частные клиники, расписание, ДМС и запись

Демо-режим показывает основной сценарий МедКарты целиком:

```
свободный текст → понимание запроса → строгая фильтрация → доступный врач
→ свободный слот → запись → изменение статуса слота → подтверждение → маршрут
```

Всё, что в демо-режиме касается частных клиник, врачей, расписания, цен и
программ ДМС, **вымышлено** и помечено «Демо». Запись — симуляция: она живёт
только в базе МедКарты, в клиники, страховые, МИС и уведомления ничего не
уходит, персональные данные пациента не запрашиваются и не хранятся.

## Включение

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DEMO_DATA=on` | выкл. (в `npm run dev` — вкл.) | демо-набор, запись, демо-аккаунты |
| `DEMO_BOOKING=off` | запись включена с `DEMO_DATA` | выключить симуляцию записи |
| `DEMO_BOOKING_DB_PATH` | `var/demo/booking.sqlite` | файл базы записей |
| `DEMO_NOW` | текущее время | «заморозить» время демо (не действует в `NODE_ENV=production`) |
| `PUBLIC_CLINICS=on` | в демо — скрыты | показывать государственные клиники и в демо |

Нужен Node 22.13+ (`node:sqlite`). На старом Node запись выключается сама,
остальной демо-режим работает.

### Запуск и сброс

```bash
npm run demo:generate   # пересобрать data/demo/generated.js (детерминированно, seed в генераторе)
npm run demo:reset      # удалить все демо-записи, вернуть слоты к исходным
npm run build && DEMO_DATA=on npm start
# или: npm run dev        — демо включено по умолчанию
```

Для показа с «замороженным» временем:

```bash
DEMO_NOW=2026-10-12T12:00:00+03:00 npm run demo:reset
DEMO_DATA=on DEMO_NOW=2026-10-12T12:00:00+03:00 npm start
```

`demo:reset` можно запускать при работающем сервере: сброс — одна транзакция.
Реальные данные (справочник врачей госучреждений, OSM, собранные клиники,
кабинет, аналитика) он не трогает.

## Государственные клиники

В демо-режиме государственные учреждения скрыты из выдачи — и на карте, и в
справочнике ассистента (`backend/demo/flags.js`). Данные ОМС и вся логика
(подсказки «по ОМС — с направлением», Госуслуги) на месте: `PUBLIC_CLINICS=on`
или выход из демо (`?demo=0`) возвращают их без перезапуска сборки.

## Данные (`backend/demo/generator.js` → `data/demo/generated.js`)

- 12 клиник, 16 филиалов, 74 врача, 16 специальностей, 38 услуг, взрослый и
  детский приём, цены по уровню клиники (эконом / стандарт / премиум).
- Точки филиалов — жилые кварталы Казани на графе дорог; адрес условный
  («демо-адрес»), телефоны `+7 (843) 000-…`, сайты `*.example`. Тест проверяет,
  что точка не совпадает с реальным учреждением из OSM.
- Идентификаторы — `demo-…` и `demo-doc-…`, с OSM и справочником не пересекаются.
- Графики: смены «утро / день / вечер / поздняя», перерывы, суббота и
  воскресенье у части врачей, отпуска (неделя) и отгулы. Врач работает только
  в филиалах своей клиники и только в часы филиала.
- Генерация детерминирована: тот же seed — тот же файл байт в байт
  (`tests/demo-data.test.js` сверяет файл с генератором).

### Слоты

Окно — 14 дней от «сегодня» по Москве; дни достраиваются автоматически.

| Поле | |
|---|---|
| `id` | `<врач>--<филиал>--YYYYMMDD-HHMM` |
| `clinicId`, `branchId`, `doctorId`, `serviceId` | |
| `start`, `end` | Europe/Moscow; `end − start` = длительность услуги |
| `status` | `FREE` / `HELD` / `BOOKED` / `BLOCKED` |
| `updatedAt` | время последнего изменения |

Исходное состояние — детерминированное: ~30 % слотов уже заняты «другими
пациентами», ~5 % закрыты клиникой. Слоты идут подряд внутри смены, без
наложений и без выхода за конец смены.

### Программы ДМС (демо)

Страховщик «Демо-Страхование», три программы с разным покрытием (модель
`shared/dms.js`: правила по филиалам, специальностям и услугам):

- **Demo Basic** — взрослая; три клиники эконом-сети; терапевт, ЛОР,
  офтальмолог, гинеколог, хирург, травматолог напрямую; невролог, кардиолог,
  эндокринолог — по направлению; процедуры не входят.
- **Demo Standard** — взрослые и дети, девять клиник; приёмы напрямую,
  процедуры — по согласованию; психиатрия и профгигиена не входят.
- **Demo Premium** — все демо-клиники напрямую; профгигиена раз в год по согласованию.

## Как это работает

```
/api/chat ── gateway: условия записи из текста (день, время, цена, город, ДМС,
   │          время в пути) — только перечислимые значения и числа;
   │          во внешнюю модель НЕ уходят
   ├─ планировщик (модель или локальный) выбирает действие
   └─ backend/demo/chatBridge.js → action.booking.request (запрос подбора)

браузер: DemoOffers → POST /api/demo/search  (+ точка отправления и программа ДМС —
                                              только здесь, в /api/chat их нет)
         BookingDialog → GET /api/demo/slots → POST /api/demo/hold
                       → POST /api/demo/bookings → «Демонстрационная запись подтверждена»
                       → маршрут тем же движком, что и обычный
```

### Строгий подбор (`backend/demo/search.js`)

Каждое условие обязательно: специальность и возраст пациента, услуга, цена,
ДМС, время в пути, день и часы. Подбор считает «воронку» — сколько кандидатов
осталось после каждого условия — и отвечает одним из статусов:

| `status` | Когда |
|---|---|
| `ok` | 1–5 вариантов: врач, клиника, цена, покрытие ДМС, время в пути, ближайшие слоты |
| `needs` | не хватает данных: `specialty`, `dms_plan` (программа не выбрана или неизвестна), `origin` (нет точки отправления при ограничении по времени в пути) |
| `empty` | никто не подошёл: какое условие отсекло последних и что даст снятие каждого (`relax` с числом вариантов) — **только как предложение** |
| `out_of_coverage` | город вне покрытия (Иннополис, Москва…) — без молчаливой подмены Казанью |
| `unavailable` | граф дорог не загружен или точка вне графа — без оценки «по прямой» |

Время в пути — тем же движком (`backend/routing/engine.js`, одним обходом на
все филиалы), без учёта пробок. Модель не может ослабить условия: они берутся
из детерминированного разбора текста, а не из её ответа.

### Запись (`backend/demo/bookingStore.js`, SQLite)

- `hold` — удержание на 5 минут (`HELD`), токен удержания знает только браузер.
- `book` — одна транзакция `BEGIN IMMEDIATE`: проверка, `UPDATE … WHERE version = ?`,
  создание записи; частичный уникальный индекс «одна подтверждённая запись на слот».
  Ключ повтора (`idempotencyKey`) — повтор после обрыва связи возвращает ту же
  запись, а не вторую. Две одновременные записи — одна проходит, вторая получает 409.
- `cancel` — по номеру и токену отмены (HMAC от секрета базы, в базе не хранится);
  прошедшее время свободным не становится.
- Записи переживают перезапуск; `demo:reset` очищает.

### API

| Метод | Путь | |
|---|---|---|
| POST | `/api/demo/search` | строгий подбор |
| GET | `/api/demo/slots?doctorId=&branchId=&from=&days=&planId=&patient=` | расписание врача со статусами и покрытием ДМС |
| POST | `/api/demo/hold`, `/api/demo/release` | удержать / отпустить слот |
| POST | `/api/demo/bookings` | записаться (`slotId`, `holdToken?`, `idempotencyKey`, `planId?`) |
| POST | `/api/demo/bookings/cancel` | отменить (`number`, `cancelToken`) |
| POST | `/api/demo/bookings/lookup` | статусы своих записей |

Записи — только JSON с того же Origin (`Sec-Fetch-Site`), лимиты запросов,
потолок тела 16 КБ. При выключенном демо — `404 demo_disabled`.

## Интерфейс

- Ответ ассистента в режиме записи повторяет понятые условия и под ним —
  блок «Свободное время» (3–5 вариантов, «Записаться», «На карте»), вопросы
  (программа ДМС — кнопками, точка отправления), честное «нет» и кнопки
  послаблений с числом вариантов.
- Диалог записи: дни и слоты с реальными статусами, услуга и цена, покрытие
  ДМС, удержание с обратным отсчётом, подтверждение, номер, маршрут, отмена.
- «Мои демо-записи» (иконка календаря в шапке): номер и токен отмены хранятся
  только в этом браузере (`medkarta.demo-bookings`), статус спрашивается у сервера.
- Карточка демо-врача: «Записаться (демо)» вместо ссылки на сайт.

## Ограничения демо

- Клиники, врачи, цены, расписание и программы ДМС вымышлены; покрытие ДМС —
  иллюстрация логики, а не страховое обязательство.
- Время в пути — без пробок и общественного транспорта по расписанию.
- Расписание и подбор — только Казань; пригороды за пределами графа — «вне покрытия».
- Запись не проверяет лимиты программы ДМС (число визитов в год) и не
  оформляет согласование со страховой — только показывает, что оно нужно.
- Отмена доступна тому, у кого есть номер и токен отмены (браузер, где записались).
