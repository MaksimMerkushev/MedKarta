# Правила неотложных состояний: на проверку врачу

Документ для врача, который будет проверять правила ассистента МедКарты. Ассистент —
навигатор: он подбирает профиль врача и запись в демо-расписании. Диагноз он не ставит,
тяжесть состояния не оценивает. Но при признаках неотложного состояния он не подбирает
запись, а советует звонить 103 или 112.

Правила написаны программистом по открытым источникам и **врачом не проверены**. Ниже —
что именно проверяется, где это в коде и какие вопросы к врачу остались.

## Как принимается решение

1. **Сначала правила на сервере** (`backend/privacy/symptoms.js`, список `RED_FLAGS`).
   Они срабатывают до любого обращения к внешней модели. Если сработало правило, текст наружу
   не уходит, подбор не начинается, человек видит совет звонить 103/112.
2. **Затем модель** (`backend/planner/triage.js`) может вернуть статус `emergency`, если
   увидела опасную картину, которую правила пропустили. Отменить срабатывание правила модель
   не может.
3. **Прошлое состояние** («после инфаркта», «был инсульт год назад», «реабилитация») —
   не вызов скорой, а поиск кардиолога или невролога (`PAST_CONTEXT`).
4. Совпадение ищется с учётом форм слов и порядка («давит в груди» = «в груди давит»).

Правило срабатывает на слова, а не на смысл. Значит, возможны оба вида ошибок: пропуск
опасного состояния, описанного необычными словами, и ложная тревога. Ложная тревога тоже
вредна: частые «звоните 103» приучают не доверять предупреждению.

## Как ассистент ведёт себя без красного флага

- Жалоба без признаков неотложного состояния ведёт к профилю врача. Если профиль неясен,
  ассистент задаёт уточняющий вопрос, а не выбирает наугад. Ребёнка ведёт к педиатру.
- «Кардиолог → болит сердце»: без признаков из правила `chest_pain` это поиск кардиолога.
- Отрицание учитывается: «в груди не болит» и «живот не твёрдый» неотложным состоянием
  не считаются (сценарии Y29, Y30, X48).

## Чем проверено

Сценарии в `tests/fixtures/ai-scenarios.js` проходят через весь путь запроса без сети
(`npm test`, `npm run ai:eval`):

- `E01`–`E14` — неотложные состояния и ложные тревоги;
- `X39`–`X48` — контрольный набор, написанный после заморозки кода. Правило
  `abdomen_progressive` добавлено после того, как первый замер провалил `X45`;
- `Y25`–`Y30` — второй контрольный набор. Двоение с головокружением добавлено после того,
  как первый замер провалил `Y27`.

Добавление правила по провалу контрольного набора делает этот набор уже не независимым.
Поэтому для врача важнее не процент прошедших сценариев, а сам список правил выше.

## Что врачу стоит проверить в первую очередь

1. Нет ли опасных состояний, которых в таблице нет вовсе (например, признаки сепсиса,
   внематочной беременности, диабетического кетоацидоза).
2. Не слишком ли широки правила `abdomen_progressive` и `fever_high`.
3. Формулировку ответа при неотложном состоянии (`buildEmergencyAction` в `backend/pipeline.js`).
4. Возрастные границы для детей.
