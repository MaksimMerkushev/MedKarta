# Продуктовая аналитика

Зачем: понять, доходят ли люди от поиска до действия (звонок, сайт,
Госуслуги, маршрут, Яндекс Карты / 2ГИС) и почему не доходят. Эти цифры —
главный аргумент в разговоре с ментором, работодателем, страховой и клиникой.

## Что НЕ собирается

- текст поиска и сообщений ассистенту (это сведения о здоровье);
- координаты пользователя и точки маршрута;
- IP-адрес, User-Agent, cookies, идентификатор диалога ассистента;
- значения фильтров (только факт «фильтр по клинике был», не какая клиника).

Do Not Track и Global Privacy Control уважаются: такие браузеры событий
не отправляют вовсе.

## Как устроено

```
браузер: track(type, поля)  →  sanitizeEvent (shared/analytics.js)
       → пачка до 20 событий, раз в 4 с и при уходе со страницы (sendBeacon)
сервер: POST /api/events → sanitizeEvent ещё раз → var/analytics/events-ДАТА.jsonl
отчёт:  npm run report:searches
```

Событие с любым лишним полем отбрасывается целиком — и в браузере,
и на сервере. Идентификатор сессии — случайная строка из `sessionStorage`
вкладки; он живёт до закрытия вкладки и ни с чем не связан.

Время в журнале — с точностью до минуты, день — по Казани. Файлы старше
`ANALYTICS_RETENTION_DAYS` (180) удаляются; в сутки пишется не больше
`ANALYTICS_MAX_EVENTS_PER_DAY` (200 000) событий.

## События

| Тип | Когда | Поля |
|---|---|---|
| `search` | поиск «устоялся» (1,5 с без изменений) | откуда (`filters`/`assistant`/`url`), специальность-код, форма собственности, список включённых фильтров, число результатов, есть ли точка отправления, потолок минут |
| `result_open` | открыта метка на карте или расписание в карточке | где, тип, форма собственности, специальность, позиция в списке, id места |
| `contact_click` | звонок, сайт, Госуслуги, официальный источник | канал, тип, форма собственности, специальность, id места |
| `route_build` | построен маршрут (или не построен) | режим, число точек, исход |
| `external_map_click` | «Яндекс Карты», «2ГИС», «На транспорте» | сервис, режим, число точек, id места |
| `feedback` | ответ на «Нашли, куда обратиться?» | ответ, причина «нет» |
| `data_report` | «Сообщить об ошибке в данных» | причина, тип, id места |

Id места — идентификатор записи справочника (`verified-…`, `osm-node-…`):
это ссылка на клинику или врача, а не данные пользователя. Без него нельзя
ни исправить запись по жалобе, ни показать клинике, сколько людей мы к ней
привели.

## Метрики отчёта

- **Успешный поиск** — после него в той же сессии и до следующего поиска было
  целевое действие: `contact_click`, `external_map_click`, удачный
  `route_build` или ответ «да». Действие приписывается последнему поиску.
- **Пустая выдача** — поиск с 0 результатов; отчёт показывает, какие фильтры
  при этом были включены, — это подсказка, каких данных не хватает.
- **Воронка по сессиям:** искали → открыли карточку → дошли до действия →
  ответили «нашёл».
- Причины «не нашёл», каналы контактов, топ мест по контактам и по жалобам
  на данные.
