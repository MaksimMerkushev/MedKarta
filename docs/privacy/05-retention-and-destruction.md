# 05. Сроки хранения и уничтожение

Принцип: данные хранятся не дольше, чем требует цель (ч. 7 ст. 5), и
уничтожаются по достижении цели, при отзыве согласия или по законному
требованию (ст. 21). Сроки ниже — по коду (значения по умолчанию; часть
меняется в админ-панели). Очистка выполняется раз в час
(`runMaintenance` в `backend/api/accountContext.js`).

## Сроки

| Данные | Где | Срок | Как уничтожается |
|---|---|---|---|
| Аккаунт, избранное, аватар, факторы MFA, знакомые устройства, дни активности | `users` и связанные таблицы (`ON DELETE CASCADE`) | пока действует аккаунт | удаление аккаунта (сам пользователь или администратор с `users.delete`) |
| Дни активности (`user_activity`) | база аккаунтов | 400 дней | автоматически ([03](03-findings.md), R9: срок на пересмотр) |
| Сессии | `sessions` | 14 дней без активности, не дольше 30 дней; сотрудники — 30 минут / 12 часов | автоматически; выход; отзыв |
| История входов | `auth_events` | 90 дней (`retention.authEventsDays`, 30–365) | автоматически; при удалении аккаунта — сразу |
| Журнал действий сотрудников | `audit_log` | 365 дней (`retention.auditDays`, 90–1825) | автоматически; свои действия удалённого аккаунта — псевдонимизация сразу |
| Ссылки-приглашения, заявки на регистрацию | `access_tokens`, `registrations` | 30 дней после истечения | автоматически; при удалении аккаунта — заявки сразу |

## Удаление аккаунта

Пользователь — профиль → «Мои данные» → «Удалить аккаунт» (со свежим
подтверждением личности и вводом слова «удалить»); администратор — карточка
пользователя (право `users.delete`). В одной транзакции
(`eraseUser` в `backend/accounts/service.js`):

1. в журнале согласий по каждой действующей цели — запись «закрыто»;
2. удаляются история входов, письма в очереди (по хэшу адреса), заявки на
   регистрацию с этим адресом, текст обращений (сами обращения остаются без
   привязки к аккаунту — для подтверждения, что на них ответили);
3. удаляется аккаунт (каскадом — сессии, избранное, аватар, MFA, устройства,
   дни активности);
4. в записях журнала действий, где автор — сам аккаунт, имя и email
   заменяются меткой «Удалённый аккаунт»; записи о действиях сотрудников над
   аккаунтом сохраняют метку до срока журнала (подотчётность персонала);
5. после фиксации транзакции — строка в `erasures.jsonl` (id и время, без
   email); снимается связь демо-записей с аккаунтом.

Проверка — `tests/privacy-152fz.test.js` («удаление: …»): после удаления ни в
одной таблице, кроме журнала согласий и журнала действий, нет ни email, ни id.

## Резервные копии

Копия базы — та же база персональных данных. Порядок:

1. Копию делать командой с шифрованием:
   `BACKUP_ENCRYPTION_KEY=… npm run accounts -- backup --encrypt --out /backup/accounts-$(date +%F).enc`
   (AES-256-GCM; ключ — 32 байта, `openssl rand -base64 32`).
2. Ключ копий хранить **отдельно** от копий и **отдельно** от `.env` с
   `MFA_SECRET_KEY` (сейчас `docs/deployment.md` советует копировать `.env`
   вместе с базой — это нужно изменить при настройке копирования: `.env` —
   в отдельное хранилище секретов).
3. Место хранения копий — в РФ ([10](10-processors-and-localization.md)),
   срок — [ТРЕБУЕТСЯ ЗАПОЛНИТЬ] (например, 30 дней), старые копии удаляются.
4. Восстановление: `npm run accounts -- decrypt-backup --in … --out …`, замена
   базы, затем **обязательно** `npm run accounts -- reapply-erasures` —
   повторяет удаления, сделанные после создания копии.

## Подтверждение уничтожения

При уничтожении по требованию субъекта, по достижении цели или при отзыве
согласия оператор оформляет подтверждение по требованиям приказа
Роскомнадзора от 28.10.2022 № 179: акт об уничтожении и (для
автоматизированной обработки) выгрузку из журнала регистрации событий в
информационной системе. Источники для выгрузки: запись `user.delete` в
`audit_log` (кто, когда, какой id), строка в `erasures.jsonl`, записи
`closed` в `consent_log`. Форма акта, ответственный и порядок хранения актов —
[ТРЕБУЕТСЯ ЗАПОЛНИТЬ ОПЕРАТОРОМ] (проверить требования приказа юристу).
