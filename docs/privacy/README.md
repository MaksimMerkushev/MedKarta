# Персональные данные: 152-ФЗ в МедКарте

Рабочий комплект документов по обработке персональных данных в МедКарте:
аудит потоков данных по фактическому коду, правовые основания, решения,
внедрённые в коде, и то, что остаётся за оператором и юристом.

> **Статус на 26.10.2026.** Это техническая и организационная подготовка, а не
> заключение о соответствии. Реквизиты оператора не заполнены
> (`[ТРЕБУЕТСЯ ЗАПОЛНИТЬ ОПЕРАТОРОМ]`), местоположение серверов, почтового
> сервиса и поставщика языковой модели не подтверждено, уведомление в
> Роскомнадзор не подавалось, документы не прошли юридическую проверку. Пока
> это так, говорить о соответствии 152-ФЗ нельзя — ни про сервис целиком, ни
> про отдельную функцию.

Тексты для пользователей — в `legal/` (политика, пользовательское соглашение,
проект согласия на сведения о здоровье). Они публикуются на сайте по адресам
`/legal/privacy`, `/legal/terms`, `/legal/health-consent`; каждая редакция —
отдельный файл, его SHA-256 записан в `legal/manifest.json`
(`scripts/legal-manifest.mjs`). Опубликованную редакцию не правят: новая
редакция — новый файл.

## Что сделано в коде (кратко)

- **Документы и редакции.** Политика и соглашение — версионируемые файлы с
  хэшем; изменённый после публикации текст не выдаётся и не принимается.
  Пока в документах есть метки `[ТРЕБУЕТСЯ ЗАПОЛНИТЬ ОПЕРАТОРОМ]`, открытая
  регистрация закрыта (`legal_documents_incomplete`); на тестовом стенде её
  можно открыть `LEGAL_DRAFTS_ALLOWED=on` (в production флаг не действует).
- **Регистрация.** Отдельная отметка «Принимаю Пользовательское соглашение»
  (по умолчанию снята) и отдельное пояснение со ссылкой на политику. Согласие
  «на всё» не собирается: данные аккаунта обрабатываются для исполнения
  соглашения. Сервер без отметки и с устаревшей редакцией аккаунт не создаёт.
- **Журнал согласий** (`consent_log`, схема 7): только добавление (триггеры
  запрещают UPDATE и удаление раньше срока), цепочка SHA-256 по каждому
  пользователю, без email и IP.
- **Сведения о здоровье.** Запрос к ассистенту не связан с аккаунтом (пропуск
  `mk_ai` без id), жалобы и профиль, выведенный из них, внешней модели не
  передаются (`local_only`), в журналах их нет.
- **Права субъекта.** Профиль → «Мои данные»: принятые редакции, выгрузка
  всех данных (JSON), обращения со сроками, удаление аккаунта. Админ-панель →
  «Обращения по ПДн» (право `privacy.requests`).
- **Удаление.** Аккаунт, журнал входов, письма в очереди, заявки на
  регистрацию, текст обращений; свои записи в журнале действий —
  псевдонимизируются; метка удаления вне базы — для повторного удаления после
  восстановления копии (`npm run accounts -- reapply-erasures`).
- **Хранение вне РФ.** Облачный Upstash для Token Vault отключён в коде.
- **Резервные копии.** `npm run accounts -- backup --encrypt` (AES-256-GCM,
  ключ `BACKUP_ENCRYPTION_KEY`).

Проверки — `tests/privacy-152fz.test.js`, сквозные сценарии в
`scripts/e2e-register.mjs` (регистрация, «Мои данные») и
`scripts/e2e-admin.mjs` (обращения, ассистент).
