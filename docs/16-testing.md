## Как устроены тесты

- [tests/helpers.js](../tests/helpers.js): конвейер на фикстуре справочника,
  Token Vault в памяти с тестовым секретом, **записывающий планировщик** — он
  сохраняет всё, что ушло бы в сеть, и именно эти записи проверяют тесты на
  утечку.
- Фикстуры: [fixtures/catalog.js](../tests/fixtures/catalog.js) (врачи с
  однофамильцами), [fixtures/roadGraph.js](../tests/fixtures/roadGraph.js)
  (синтетический граф), `fixtures/sites/` (страницы для сборщика),
  `fixtures/legacy-demo/` (прежний формат демо-данных).
- Время в сценариях демо-записи заморожено: понедельник 12.10.2026, 12:00 МСК.
- Режим исходящего запроса берётся из `PRIVACY_OUTBOUND_MODE`, поэтому
  `npm run test:security` прогоняет весь набор в обоих режимах; тесты одного
  режима задают его явно.
- Тесты с `node:sqlite` пропускаются на Node без него (`skip: 'нужен Node 22.13+'`).

## Команды

```bash
npm test                                 # все тесты, режим structured
npm run test:hybrid                      # все тесты, режим hybrid
npm run test:security                    # оба прогона подряд
node --test tests/demo-scenarios.test.js # один файл
npm run eval:privacy                     # полный размеченный набор (~минута)
npm run lint
npm run test:e2e                         # сквозные проверки: админ-панель, вход и приглашения, регистрация и письма (нужны dist/ и Playwright)
npm run test:e2e:auth                    # вход, второй фактор, приглашения: 375/768/1440, клавиатура, reduced motion
npm run test:e2e:register                # регистрация, восстановление, смена email, TOTP — с учебным SMTP-сервером
node --test tests/secure-auth.test.js    # регистрация, MFA, защита входа, почта, миграция
```

Сквозные проверки поднимают сервер сами — на временной базе, на
`localhost` (ключи доступа WebAuthn не работают на IP-адресе), с
`MFA_SECRET_KEY` на один прогон. Ключ доступа — виртуальный (WebAuthn через
протокол отладки Chromium: настоящая церемония в браузере, ключ в памяти
теста), коды TOTP вычисляются из секрета, показанного на странице, письма
принимает учебный SMTP-сервер ([fixtures/smtpServer.js](../tests/fixtures/smtpServer.js))
на `127.0.0.1` — настоящие адреса не используются. Общие части —
[scripts/e2e-lib.mjs](../scripts/e2e-lib.mjs).

## Чего тесты не покрывают

- **Интерфейс.** Модульных тестов React-компонентов в репозитории нет;
  тестами покрыты чистые модули фронтенда (`bestPicks.js`, `placeList.js`,
  `externalMaps.js`, `booking.js`, `shared/qr.js`), а вход, второй фактор,
  регистрация, приглашения, профиль и админ-панель — сквозными проверками
  `npm run test:e2e` в браузере (Chromium; Firefox и Safari не проверялись). Карта, ассистент и запись в e2e не
  входят.
- **Настоящая модель.** Качество плана реальной модели не проверяется —
  везде заглушка; для ручной проверки есть `npm run ai:check`, `ai:bench`,
  `ai:trace` ([06-ai-assistant.md](06-ai-assistant.md)).
- **Сборка фронтенда** в `npm test` не входит.
- **Нагрузка.** Отдельных нагрузочных тестов нет; лимиты и предохранители
  проверяются модульно.
