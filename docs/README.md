# Техническая документация МедКарты

МедКарта — медицинский навигатор по Казани: карта врачей и медицинских
учреждений, фильтры, маршруты по дорогам собственным движком и ассистент,
который понимает запрос обычными словами. Слова пользователя, имена,
контакты и описания жалоб внешней языковой модели в режиме по умолчанию не
передаются: для планирования она получает ограниченное структурированное
описание запроса, включая профиль врача. Что такое описание всё же
раскрывает и какие риски остаются — в [07-privacy.md](07-privacy.md).

Эта документация — техническая база знаний проекта. Она описывает
**состояние кода в конкретном коммите** и опирается на код как на источник
истины: всё, что здесь утверждается, проверено по исходникам, тестам или
воспроизводимым замерам. Если что-то проверить не удалось, это сказано прямо
(раздел «Что не удалось проверить» в [18-known-limitations.md](18-known-limitations.md)).

## Статусы возможностей

Каждая возможность в документации помечена одним статусом:

| Статус | Значение |
|---|---|
| **Implemented** | Реализовано в коде и покрыто тестами или проверено запуском |
| **Partially Implemented** | Реализована часть: например, код есть, но не подключён, или работает только при условии |
| **Demo** | Работает на вымышленных данных демо-режима (`DEMO_DATA=on`) и не связано с реальными организациями |
| **Mock** | Заглушка или упрощённая модель вместо настоящей интеграции |
| **Planned** | Описано в документах проекта как будущая работа; кода нет |
| **Unknown** | Подтвердить по репозиторию нельзя (например, зависит от файлов вне git или от настроек сервера) |

## Как читать эту документацию

- **Новому разработчику:** 01 → 02 → 03 → 15 (локальный запуск) → 16.
- **Ревьюеру безопасности и приватности:** 07 → 08 → 18, затем
  [privacy-architecture.md](privacy-architecture.md).
- **Про ассистента:** 06 → 07 → 11 → 12 (`/api/chat`, `/api/demo/*`).
- **Про маршруты:** 09 → 17.

Ссылки на исходный код — относительные (`../backend/server.js`): они работают
при просмотре на GitHub. На сайте документации (GitHub Pages) такие ссылки
ведут на файлы того же коммита `d9c0de6` в репозитории, а ссылки на файлы
самой документации, кроме страниц (например, скрипты в `docs/tools/`), — на
ветку `main`.

## Просмотр

- **На GitHub** — откройте любой `.md` в каталоге `docs/`; диаграммы Mermaid
  GitHub рисует сам.
- **Как сайт** — <https://docs.navimed.tech> (GitHub Pages,
  [docsify](https://docsify.js.org)): каталог `docs/` содержит `index.html`;
  публикация — Settings → Pages → Build and deployment → Deploy from a branch →
  ветка `main`, папка `/docs`. Адреса страниц — без «#», например
  `docs.navimed.tech/09-routing-engine`; подробности —
  [15-deployment.md](15-deployment.md).
- **Локально** — любым статическим сервером из каталога `docs/`, например
  `python3 -m http.server 8000 --directory docs`, затем
  `http://localhost:8000`. Внутренние страницы открывайте переходом с главной:
  простой сервер не отдаёт `404.html`, поэтому обновление внутренней страницы
  даёт ошибку 404. Скрипты docsify и Mermaid загружаются с CDN
  `cdn.jsdelivr.net`, поэтому нужен доступ в интернет.
