# Статистика для суперадминистратора

Раздел админ-панели `/admin/stats`, разрешение `stats.view`: его нельзя выдать
никому, кроме суперадминистратора. Только сводные числа: адресов, id
пользователей, параметров и текстов запросов здесь нет.

## Период

Готовые варианты (сегодня, вчера, 24 часа, 7, 30, 90 дней, этот и прошлый месяц,
этот год) или свои даты; время московское. Шаг графика — час, день, неделя,
месяц: автоматически по длине периода или свой, если помещается в 400 точек
(иначе экран скажет, что шаг изменён). Итоги сравниваются с прошлым периодом той
же длины. Кнопка CSV выгружает графики и таблицы текущей вкладки.

## Откуда какие числа

| Вкладка | Источник | Точность | Глубина |
|---|---|---|---|
| Запросы | `http_hourly` | по часам | 400 дней, но не раньше первой выкладки |
| Ассистент | `metric_daily`; запросы к `/api/chat` — `http_hourly` | по суткам | 400 дней, но не раньше первой выкладки |
| Поиск и карта | журнал аналитики, свод по завершённым суткам — `product_daily` | по суткам | 180 дней журнала, своды — 400 |
| Пользователи | база аккаунтов | часы для входов и новых, сутки для активности | входы — `retention.authEventsDays` (90), активность — 400 дней |
| Запись | база демо-записи | по моменту записи | пока запись есть в базе |
| Письма | очередь `mail_outbox` | по моменту постановки | 30 дней |

История запросов начинается с первой выкладки раздела: раньше счётчик жил только
в памяти процесса, и восстановить её не из чего. На экране это написано.

Раньше срока теряется только последняя минута: счётчики пишутся раз в минуту и при
остановке сервера (SIGTERM, SIGINT), а при падении процесса — нет. В режиме
`npm run dev` счётчики запросов не ведутся: их пишет `backend/server.js`.

## База статистики

Отдельный файл `stats.sqlite` рядом с базой аккаунтов (`STATS_DB_PATH`,
`STATS=off` выключает сбор). При выкладке переносится вместе с `var/`. Отдельно
от аккаунтов намеренно: схеме аккаунтов не нужна миграция, откат выкладки
безопасен, частая запись не касается файла с персональными данными.

| Таблица | Что хранит |
|---|---|
| `http_hourly` | час, строка адреса, число запросов, классы ответов и отказы 429, суммарное время, гистограмма времени ответа |
| `metric_daily` | сутки, счётчик процесса (`metrics.js`) с перечислимыми метками, значение |
| `product_daily` | сутки и свод журнала аналитики |

Время ответа: среднее точное, p50 и p95 — верхняя граница корзины гистограммы
(25, 50, 100, 250, 500, 1000, 2500, 5000, 10000 мс), поэтому приблизительные.

## Приватность

- **Адрес обезличен** ([endpoints.js](../backend/stats/endpoints.js)): сегмент,
  похожий на идентификатор, становится `:id`, ответ 404 считается как `unknown`,
  статика — одной строкой, на час не больше 300 строк. Параметров запроса нет.
- **Счётчики процесса — только по суткам.** Среди них признаки здоровья (триаж,
  срочные случаи); почасовая строка при малом трафике сопоставлялась бы по времени
  с журналом nginx. По этой же причине их нет в построчном журнале.
- **Обращения к ассистенту не разбиваются по людям — и не должны.** Ассистент
  намеренно не связан с аккаунтом, жалоба — сведения о здоровье. По пользователю
  доступны только входы и активность (карточка пользователя).
- **Посетителей по IP не считаем.** В статистике сессии из журнала аналитики:
  случайная строка вкладки, не связанная с человеком.
- Новых категорий персональных данных раздел не вводит. Названия врачей и клиник
  в списках «чаще всего открывают» — из публичного справочника.
