# Данные: частные клиники, цены, ДМС и их актуальность

## Модель

```
клиника ──┬── филиал (адрес, часы, телефон, координаты)
          │      ├── врачи (специальность, часы, детский приём)
          │      └── цены услуг (услуга из справочника, дата)
          └── …

страховая ── программа (взрослая / детская / семейная, срок действия)
                 └── покрытие: программа × филиал × (вся амбулатория | специальность | услуга)
                               режим доступа: напрямую / через пульт / по направлению /
                               по согласованию / исключено; возраст; лимиты
```

- **Филиал, а не клиника.** Адрес, часы и покрытие ДМС привязаны к конкретному
  адресу. «Клиника входит в мой ДМС» почти никогда не правда целиком.
- **Программа, а не работодатель.** У двух сотрудников одной компании
  программы бывают разными. Дети застрахованы отдельной программой.
- **Услуги** сводятся к закрытому справочнику (`shared/services.js`) с кодами
  номенклатуры медуслуг (приказ № 804н). «Приём ЛОР-врача», «Консультация
  оториноларинголога» и «Осмотр отоларинголога» — одна услуга, иначе цены
  не сравнить. Пакеты, «на дому», онлайн-консультации и смежные профили
  (кардиохирург ≠ кардиолог) намеренно не сопоставляются.

Код: `shared/privateCatalog.js` (проверка и разворачивание в карточки),
`shared/dms.js` (покрытие), `shared/services.js` (услуги и цены).

## ДМС в интерфейсе (уровень 1)

Пользователь выбирает страховую и программу в «Мой ДМС». В браузере
сохраняется **только id программы** (`localStorage`, ключ `medkarta.dms.plan`).
Номер полиса, ФИО и работодатель не нужны и не спрашиваются. Покрытие
считается в браузере; на сервер программа не уходит. В аналитику попадает
только «программа выбрана: да/нет».

Ассистент понимает «есть ДМС» (`dms_only`) и включает фильтр; если программа
не выбрана, открывается «Мой ДМС».

## Демо-режим

`data/demo/` — вымышленные клиники («Демо-…»), цены, страховые и программы.
Сайты — в зоне `.example`, телефоны — с кодом 000. Нужны, чтобы проверять
сценарии, для которых реальных данных ещё нет.

- Сервер: `DEMO_DATA=on` (в `npm run dev` включено по умолчанию).
- Интерфейс следует серверу (`/api/config`); вручную — `?demo=1` / `?demo=0`.
- В интерфейсе демо-записи помечены «Демо», над фильтрами — плашка.

## Сборщик данных

```
data/sources.json → загрузка → разбор → сравнение со снимком → применение / очередь
                                                     data/collected/<источник>.json
                                                     data/review/pending.json
```

| Команда | Что делает |
|---|---|
| `npm run data:collect` | обходит источники, применяет безопасные изменения, остальное — в очередь |
| `npm run data:collect -- --source <id> --version v2` | один источник; для файловых — другая версия файла |
| `npm run data:review` | очередь проверки; `--accept <id>` / `--reject <id>` |
| `npm run data:build` | снимки → `data/private/catalog.json` (только без ошибок) |
| `npm run data:verify` | проверка госврачей на страницах учреждений → `data/verification.json` |

**Разбор:** JSON-LD schema.org (`MedicalClinic`, `Physician`, `employee`) и
HTML-таблицы прайса. Не разобралось — не «додумываем», а отдаём человеку.

**Новый источник** попадает в справочник только после подтверждения: первый
прогон заводит снимок и ставит в очередь один пункт «новый источник: клиника,
врачей N, цен M». Пока он не принят, `data:build` источник пропускает.

**Что применяется само:** часы клиники; новый врач; часы врача; новая цена;
изменение цены до 20 % — считая от последней цены, которую видел человек
(ступеньки по 19 % за прогон не накапливаются).

**Что ждёт человека:** телефон, сайт, адрес, координаты, название; врач пропал
со страницы; сменилась специальность; цена изменилась больше чем на 20 %;
услуга пропала из прайса; строка прайса не сопоставилась с услугой. Телефон и
сайт — потому что именно их подменила бы взломанная страница: они стоят на
кнопках «Позвонить» и «Записаться». Если пропало больше половины врачей или
цен или появилось больше, чем было, — это почти наверняка смена вёрстки или
подмена, и **весь** прогон уходит на проверку, ничего не применяется. Больше
400 врачей или 1500 цен на одной странице — тоже на проверку.

Отклонённое изменение больше не предлагается. Неизменная страница (тот же
хэш или ответ 304) только обновляет дату проверки.

**Вежливость и осторожность:** свой User-Agent с контактом (`DATA_BOT_CONTACT`),
robots.txt, не чаще запроса в секунду к сайту, условные запросы (ETag,
Last-Modified), потолки размера (3 МБ, считая по мере чтения) и времени.
Редиректы — только в пределах того же сайта; локальные и внутренние адреса
запрещены. Сайт клиники в справочнике — только того же домена, что источник.
Подробнее — раздел «Сборщик данных» в `SECURITY.md`. Брать данные только с официальных сайтов клиник;
копировать агрегаторы (ПроДокторов и т. п.) нельзя — их условия это запрещают.

**Демо:** в `data/sources.json` два демо-источника — локальные страницы
вымышленных клиник (`data/demo/sites/`). Версия `v2` «Демо-Здоровья»
показывает все типы изменений:

```bash
npm run data:collect                                                   # завести снимки
npm run data:review -- --accept <id>                                   # подтвердить новый источник
npm run data:collect -- --source demo-zdorovie-center-site --version v2
npm run data:review
```

Снимки демо-источников в git не попадают; в `data:build` демо не входит
(для проверки — `--include-demo --out /tmp/catalog.json`). Очередь проверки
(`data/review/`) тоже не коммитится: в ней сырой текст со страниц. Принятое
оказывается в снимках `data/collected/` — их изменения видны в git.

## Проверка госврачей

`npm run data:verify` открывает страницу, с которой взят каждый врач
(`sourceUrl`), — один раз на всех врачей страницы — и ищет его по фамилии и
имени. Найден — дата проверки обновляется; не найден — в карточке
предупреждение «при проверке врача не нашли, уточните по телефону»; страница
недоступна — дата не меняется (и стареет на виду). Результат — только id и
даты, без имён. Запускать там, где есть доступ к сайтам больниц (на своём
компьютере или сервере), например раз в неделю.
